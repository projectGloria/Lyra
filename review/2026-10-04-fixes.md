# Lyra audit fixes

Date: 4 October 2026. Implements the fixes requested after the [audit](<C:/Users/Nihil/Desktop/Github Repos/Lyra/review/2026-10-04-audit.md>).

## Changes

| Finding | Result |
|---|---|
| B1: failed playlist-cover save | Artwork is staged and original covers are retained in recovery files until metadata commits. Removal and replacement roll back on failure. Recovery files remain available if restoration itself fails. |
| B2: seek applied to another track | A pending seek includes its playback request and track path; a new selection discards it. Startup and both editors pass resume positions through this mechanism. |
| B3: queue/history cursor | History now carries queue origin and playlist anchor. A forward stack lets Next retrace songs visited with Previous. The contexts persist with playback sessions and follow folder renames. |
| B4: stale playlist artwork | Successful playlist-cover changes invalidate the corresponding shared artwork index. |
| B5: search keyboard focus | Search selects a focus ID from the displayed collection. Virtual rendering keeps one rendered row in the tab order when the remembered row is offscreen. |
| P1: show-all search | Search songs reuse the virtual track list; HTML size and rendered row count stay bounded by the viewport. |
| P2: incremental scan work | Scans reuse unchanged collection tracks, create metadata jobs for changed or retryable files, avoid redundant natural sorting, insert new files into existing natural order, and purge only explicitly removed cache records. Copy-on-write cache updates clone one of 64 shards rather than the complete metadata map. Existing cache files remain compatible. |
| P3: tag edits force full refresh | Native tag saves return their committed snapshot baseline and revision. The renderer advances its baseline only when the edit's base matches, retaining the safe full-scan fallback for conflicting updates. |

Incremental artwork updates still reconcile albums across folders, so deleting a cover donor cannot leave its old cover attached to recipients. Transient metadata read failures remain retryable, including in otherwise untouched folders. Manual order and fallback track numbering remain consistent with full scans.

The watcher now marks failed subscriptions unhealthy, reports interruptions, retries unavailable roots automatically, and requests a full refresh after recovery. Debounced change batches have a one-second maximum delay so continuous imports cannot starve updates. Managed artwork recovery files are ignored by the watcher and are not swept as disposable temporary files.

The Tauri CSP configuration now explicitly restricts scripts, objects, frames, and other resource types while permitting local media, selected artwork, and native IPC. The page already had an HTML CSP; the audit's original security observation overstated the absence of protection. Rust formatting differences were also resolved.

## Performance measurements

Search measurements use the actual search and virtual-row functions with DOM and artwork/icon stubs, a 340-pixel list viewport, one warm-up, and three measured runs. Browser parsing/layout and native IPC are excluded.

| Matches | Original median HTML generation | Virtual search + visible rows | Generated HTML after fix |
|---:|---:|---:|---:|
| 1,000 | 11.3 ms | 1.9 ms | 26.7 KiB, 29 rows |
| 10,000 | 117.3 ms | 11.5 ms | 26.7 KiB, 29 rows |
| 50,000 | 555.9 ms | 57.5 ms | 26.7 KiB, 29 rows |

Native scan timings use temporary valid WAV fixtures and the actual scanner/cache modules in a debug build, without a Tauri window. These are single-run workload examples, not release-build forecasts. Final measurements were taken after the production build completed.

| Library layout | Original warm full scan | Final warm full scan | Original one-file refresh | Final one-file refresh |
|---|---:|---:|---:|---:|
| 1,000 tracks, one folder | 343 ms | 322 ms | 126 ms | 67 ms |
| 5,000 tracks, one folder | 2,195 ms | 2,083 ms | 599 ms | 306 ms |
| 5,000 tracks, 100 folders | 1,240 ms | 1,174 ms | 273 ms | 102 ms |

Some whole-library work remains: snapshot copying, delta comparisons, and cross-folder album artwork reconciliation still scale with library size. The change removes unnecessary metadata jobs, cache eviction passes, full-map copy-on-write, and repeated sorting rather than claiming constant-time refreshes.

## Limits

Personal music and stored application settings were not modified during validation. The release executable is built in `src-tauri/target/release/lyra.exe`; an installer was not rebuilt or installed. Live WebView layout, real audio devices, removable/network-drive disconnects, GPU/battery behavior, and crash-time recovery of a multi-file artwork save have not been exercised. Original cover recovery files are retained if a process stops before the transaction completes.
